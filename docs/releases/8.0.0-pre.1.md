# Release 8.0.0-pre.1

**Release:** `8.0.0-pre.1`

`8.0.0-pre.1` is the first release candidate for the cleaned Control Plane,
normalized PostgreSQL model and React operator console. It is a pre-release:
promotion to `8.0.0` requires the live evidence listed below.

## Included Baseline

- Replaces the legacy Web UI with the typed React frontend and keeps the API as
  the only authority for persisted state.
- Removes the superseded VLESS membership registry in favor of global client
  access groups that materialize access into every in-scope instance.
- Normalizes retained PostgreSQL relationships, adds missing integrity
  constraints and extends the migration drill schema checks.
- Preserves external-provider isolation: only assigned access groups use the
  provider route; the node main route is not replaced.
- Hardens agent HTTP transport. Remote cleartext Control Plane URLs now fail
  closed unless an explicit temporary compatibility override is configured.
  Operators can install a private CA and an optional client certificate/key.
- Makes security-sensitive audit writes fail closed for login success,
  bootstrap-secret reveal and browser-terminal issuance/start.
- Reports failed agent inventory submission instead of silently discarding the
  error.
- Hardens SMTP delivery with TLS policy, bounded recipients and attachments,
  header validation, deadlines and explicit delivery-state handling.
- Rejects unsafe or relative public mail-action URLs before creating an invite
  or publishing a share link.
- Refines the external provider editor: only ready protocols are selectable,
  the form is organized by operator task, modal content scrolls on compact
  screens and action rows are stable.
- Applies shared responsive HTML email styling to operator invitations and
  client access delivery. Desktop and 390 px mobile previews have no horizontal
  overflow.

## Compatibility And Upgrade

- PostgreSQL migrations through the repository head are mandatory. Stop API
  and worker processes, run `cmd/migrate`, then start the new binaries.
- Update API, worker and all node agents together. A node agent configured with
  a non-loopback `http://` Control Plane URL will refuse to start unless
  `MEGAVPN_AGENT_ALLOW_INSECURE_HTTP=true` is explicitly set. This override is
  only for a bounded migration window.
- For private PKI, set `MEGAVPN_AGENT_TLS_CA_FILE`. Optional client identity is
  configured with both `MEGAVPN_AGENT_TLS_CERT_FILE` and
  `MEGAVPN_AGENT_TLS_KEY_FILE`; partial configuration is rejected.
- `MEGAVPN_PUBLIC_BASE_URL` and `MEGAVPN_OPERATOR_INVITE_BASE_URL` must use
  absolute HTTPS URLs when the corresponding email workflow is used. HTTP is
  accepted only for loopback development endpoints.

## Promotion Gates

The following evidence is mandatory before tagging stable `8.0.0`:

1. Apply all migrations from zero on disposable PostgreSQL, run schema
   invariants, re-run migrations where supported, then complete backup/restore.
2. Deploy API, worker and agent to disposable nodes and verify heartbeat,
   signed job polling, inventory and runtime drift.
3. Run the staged service matrix, including L2TP/IPsec, OpenVPN, WireGuard,
   Shadowsocks and VLESS camouflage.
4. Verify VLESS data plane, HTTP-to-HTTPS, fallback website, selected
   egress/backhaul and nft/ip-rule/route-policy state.
5. Verify instance deletion, emergency cleanup, full wipe and orphan artifact
   cleanup on a disposable node.
6. Verify OpenVPN, WireGuard and Xray accounting collectors with real traffic.
7. Run `scripts/ci/release-gate.sh` with all production evidence variables.

## Known Architectural Debt

- The HTTP package still exposes a broad store contract and several large
  handler files. Use-case extraction must continue incrementally; it is not a
  safe big-bang change for this pre-release.
- PostgreSQL best-effort audit calls that must become atomic require a
  transactional audit/outbox design. Security-boundary HTTP actions already
  fail closed, but a repository-wide transactional outbox remains an `8.0.0`
  promotion item.
- Mandatory mTLS for the agent channel remains a deployment decision. HMAC
  signing is mandatory; HTTPS is now fail-closed for non-loopback endpoints and
  optional client certificates are supported.

## Validation

Repository unit, race, static, frontend, documentation and build gates are run
for this branch. Live PostgreSQL and node/data-plane gates are deliberately not
represented as passed unless their external evidence is supplied.
